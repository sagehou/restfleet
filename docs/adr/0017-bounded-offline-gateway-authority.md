# 独立 Gateway 使用有界离线授权与加密待回写区

现有 Gateway 在线核验、审计和 token 刷新依赖 PostgreSQL，无法满足控制面失联时继续备份的要求。用户已接受：独立 Gateway 使用中心签发、只可在线续期的有界离线授权，并将审计与 OAuth 刷新记录可靠写入本地有界加密待回写区，恢复后由中心验证、幂等入库；PostgreSQL 仍是唯一控制面权威。代价是控制面失联时撤销/禁用最多延迟 12h 生效，授权到期、容量耗尽或无法安全持久化时 MUST fail closed。

## 后果

- Gateway MUST NOT 持有 Server master key、Restic repository password、Server 数据库凭据或中心授权签名私钥；本地记录加密与来源认证 MUST 分别建立，不得把“可以加密”当作可信来源证明。
- 授权期限 MUST 从中心签发时间计算，不能从接收、重放或检测到失联时重新计时。续期 MUST 重新验证当前绑定、精确 ACK、状态、owner 与未释放占用，并防止旧授权回滚或跨运行实例复用。
- ADR-0016 的“到期不释放 fence”保持不变。离线授权不授予维护权；新 owner MUST NOT 仅凭 UUID、文件锁或授权到期接管，回写排空也不能单独证明旧请求/子进程已退出。
- Gateway 持续运行是离线能力的前提；Gateway 重启或丢失运行材料时不承诺离线恢复。恢复协调 MUST 先验证记录、完成持久化并确认旧数据面清理，才允许释放占用或恢复冲突写入者。
- 12h 撤销上限不自动证明任意失联时刻之后都有完整 12h 可用授权。实现 MUST 验证续期边界及剩余时间，不得通过接收端延寿突破撤销上限，也不得把缩短的离线实验算作 AGT-005 通过；如果两项要求无法同时满足，MUST 提交明确取舍，不能静默降低验收。

## 未选择的方案

继续要求每次操作同步访问 DB 无法提供离线数据面；把 DB/master key 下放到 Gateway 扩大秘密边界；无限期缓存授权无法限定撤销延迟。因此不采用这些方案。

这是已批准的目标架构，不是实现完成声明。具体交付与故障验收见 [部署规范 §7.10](../spec/09-deployment.md#710-有界离线授权与待回写目标)；现有在线入口在替代实现验证前保留 fail-closed 行为。
